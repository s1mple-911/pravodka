## 0.5 🔴 Ma'lumot kontrakti (coder → UI) — UNIVERSAL

Butun dizayn shu uchta shaklga tayanadi. **Ichida "mashina" so'zi yo'q** — mashina bu
`tur==='royxat'` maydonining bitta misoli.

**(a) Maydon ta'rifi** — `xarajat_maydon` (bitta xarajat moddasiga tegishli):
```js
{ id:'uuid', account_id:'uuid', nom:'Mashina',
  tur:'royxat'|'dropdown'|'matn'|'raqam'|'sana',
  required:true, tartib:1,
  options:{ placeholder:'', choices:['Naqd','Click'] } }   // choices — FAQAT dropdown
```

**(b) Ro'yxat elementi** — `xarajat_royxat` (faqat `tur==='royxat'`):
```js
{ id:'uuid', maydon_id:'uuid', nom:'DAMAS', qiymat:'01O244RB',
  rasm_url:'https://…/maydon-rasm/…jpg'|null, tartib:1, is_active:true }
```
🔴 **`rasm_url` — TO'G'RIDAN ochiladigan URL** (public bucket `maydon-rasm`), signed URL **emas**.
Sabab: jurnalda bir sahifada 100 qator chiziladi; har rasm uchun `createSignedUrl` chaqirilsa
100 ta qo'shimcha so'rov ketardi va rasmlar sakrab-sakrab paydo bo'lardi. Chek suratlari
(`xarajat-cheklari`, private + signed) bilan **ataylab farq qiladi**: chek — moliyaviy hujjat,
maydon rasmi — katalog surati.

**(c) Yozuvdagi qiymat** — jurnal/hisobot uchun **tayyor ko'rinishda** (view `v_entry_maydon`):
```js
{ entry_id:'uuid', maydon_id:'uuid', maydon_nom:'Mashina', tur:'royxat', tartib:1,
  qiymat:'DAMAS 01O244RB',        // 🔴 KO'RSATILADIGAN matn — serverda yig'ilgan
  rasm_url:'https://…'|null }
```
🔴 **`qiymat` ni klient yig'maydi.** Aks holda jurnal, hisobot, Excel va AI to'rt xil
matn ko'rsatardi. Server qoidasi (bitta joyda):
`royxat` → `nom + ' ' + qiymat` (bo'shlar tashlanadi) · `dropdown`/`matn` → matnning o'zi ·
`raqam` → probel bilan ajratilgan son · `sana` → `YYYY-MM-DD`.

**(d) Yozishda** — forma serverga shuni yuboradi:
```js
maydonlar: [ { maydon_id:'uuid', element_id:'uuid'|null, qiymat_text:'…'|null } ]
```
🔴 `element_id` bor bo'lsa `qiymat_text` **e'tiborsiz** (manba — katalog). Element keyin
tahrirlansa eski yozuv **eski matnni saqlab qolishi** shart — shuning uchun serverda
`entry_maydon` ga `qiymat_text` **snapshot** ham yoziladi. Busiz "DAMAS" nomi o'zgarganda
o'tgan yilgi jurnal jimgina qayta yozilardi.

**Ko'rinish qoidasi (hamma sahifada bir xil):**
> **Qiymat yo'q → HECH NARSA chizilmaydi.** Bo'sh chip, "—", bo'sh rasm ramkasi — yo'q.

## 1. A — `sozlama-dev.html`: maydon konstruktori

### 1.1 🔴 Qaror — MODAL EMAS, akkordeon ham EMAS: "ochiladigan detal kartasi"

**Qaror:** modda qatoridagi **"Maydonlar"** tugmasi bosilganda ro'yxat kartasidan **keyin**
alohida karta (`#mxdCard`) paydo bo'ladi, `scrollIntoView({block:'start'})` bilan ko'rsatiladi.
Bir vaqtda **faqat bitta** modda ochiq (`mxdOpen` — bitta id). Ochiq moddaning tugmasi `.on`.

**Nega modal emas (hal qiluvchi sabab):**
Konstruktorda **ikki daraja** bor: maydon → uning ro'yxat elementlari → element rasmini yuklash.
Modal tanlansa ikkinchi daraja **modal ichida modal** bo'lardi. Repoda bu naqsh hech qayerda
yo'q va telefonda pastdan chiquvchi varaq ichida ikkinchi varaq ochilishi — fokus qopqoni,
`body:has(.modal.open){overflow:hidden}` ikki marta, Esc qaysi qavatni yopishi noaniq.
Karta esa oddiy oqim ichida turadi: ikkinchi daraja shunchaki pastga cho'ziladi.

**Nega `.item` ichiga akkordeon emas:**
Xarajat tabidagi `.item` qatorida allaqachon **7 ta interaktiv element** bor
(4 ta `.chekopt` + qalam + tugma-switch). 360px da bu qator hozir ham o'ralib ketadi.
Akkordeon uni 8-elementga aylantirib, ochilganda ichida yana ikki daraja chizardi —
268px foydali kenglikda (360 − 2×26 `.main` − 2×20 `.card`) o'qib bo'lmasdi.
Detal kartasi esa **butun 268px ni** oladi.

**Nega alohida sahifa ham emas:** yangi `.html` fayl = yangi login gate + yangi nav +
`promote.sh` `PAGES` + `perm_pages()` + `perms-dev.js` `PAGES` + `index-dev.html` `CARDS`.
Bitta admin ekrani uchun besh joyga tegish — mutanosib emas.

**Master ro'yxat yo'qolmaydi:** karta ro'yxatning **ostida** ochiladi, ustiga emas.
Admin "qaysi moddadaman" degan savolga scroll qilib javob oladi; karta sarlavhasida ham
modda nomi + kodi turadi.

### 1.2 Tartiblash — ↑ ↓ tugmalari, drag EMAS

Repoda drag-and-drop infratuzilmasi yo'q; `pointer` drag telefonda scroll bilan urishadi va
`:focus-visible` bilan boshqarib bo'lmaydi. **↑ ↓ tugmalari** — 100% touch va klaviaturabop,
har bosishda `tartib` maydonlari qayta raqamlanadi. Birinchi qatorda `↑`, oxirgisida `↓`
`disabled` (yashirilmaydi — joy sakramasin).
